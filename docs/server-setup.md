# 服务器搭建

下面所有 `YOUR_…` 都是占位符，换成你自己的值，不要把真实值提交到公开仓库。

## 1. 准备

- 一台 Linux 云服务器，能出网，能跑 Hermes。
- 服务器上装好 `adb`（Android 调试桥）。
- Hermes 已装好，能跑 `hermes` 命令；版本要满足 phone-harness 插件的要求（插件 README 里写的要求为准）。

## 2. 装 phone-harness 插件

按 phone-harness 仓库里 Hermes 集成的说明安装：

```
hermes plugins install ShawnPana/phone-harness/integrations/hermes
```

注意两点：

- 插件启用后，`phone_exec` 工具只在**新会话**里出现，旧会话看不到，要开新会话。
- 交互会话里每次 `phone_exec` 调用都会弹窗审批；单次运行（`hermes -z`）会按设计自动跳过审批，测试时要在汇报里写明这一点，不要用 `--yolo` 再叠一层。

## 3. 做 adb 转发（经已有的反向隧道）

手机的无线调试配对端口和连接端口经常会变，重启、换网后可能要重新配对。

通用做法（不要照抄端口号，按你当时的实际端口填）：

1. 手机上开开发者选项 → 无线调试，拿到配对端口、连接端口、配对码。
2. 在服务器上，经已有的反向隧道，把这两个端口转发到服务器本机（只绑本机，不要绑公网）。
3. 在服务器上做 `adb pair`（配对码只用一次，用完即废，不要记下来），再做 `adb connect`。
4. `adb devices` 看到你的手机是 `device`（已授权）状态，才算通。
5. 转发是手动进程，不是持久化：隧道断了、服务器重启了，转发就没了，adb 设备会离线，要重做转发；手机重启、换网后端口变了，可能要重新配对。

模板见 `scripts/server/adb-forward.sh`，里面只有占位符和步骤注释，没有真实地址和端口。

## 4. 放 skill

把 `skills/phone-wechat-send/SKILL.md` 放到 Hermes 的 skill 目录里（按你 Hermes 版本的 skill 存放规则放，一般是 Hermes 配置目录下的 `skills/<分类>/<名字>/SKILL.md`），然后：

```
hermes skills list
```

确认列表里能看到这个 skill，状态是 enabled，再做下一步。看不到就不要往下测，先查存放路径和格式（skill 文件头要有 `name:`、`description:`）。

## 5. 先测“自己给自己发”

不要一上来就给真人发消息。先用 `examples/wechat-send-prompt.md` 的模板，在文件传输助手这类会话里测一条，核对：

- 标题对不对
- 是不是只多了一条
- 输入框空了没有
- 输入法恢复了没有
- 阶段通知发了没有

都对了，再考虑别的会话。

## 6. 超时怎么设

实测经验：Hermes 跑一趟微信发消息，接近 10 分钟量级。

- 单次运行的超时不要设 600 秒，会被掐在输入完、没点发送那一步，留下一个“已输入、未发送、输入法没恢复”的半成品状态。
- 建议设 1200 秒；超时后不要盲目重跑，先读屏查输入框，再决定是“只点发送补发”还是“重跑”。

## 7. 隧道回来后，按顺序重建通道

隧道断过一次之后，不要只看隧道状态就开任务，转发可能还死着。
按 `docs/reliability.md` 第 1 节的顺序查：隧道探活、转发监听、
`adb devices` 的 `device` 状态、当前输入法，缺一环就先补那一环。
配对失败也不要直接当成没通：如果服务器之前已在已配对列表里，
直接 `adb connect` 可能就通了，见 `docs/reliability.md` 第 2 节。
