# 阶段通知

目标：任务进行中，用户下拉通知栏就能看到当前到哪一步，不用切进聊天看进度。

## 现在用的办法：shell 通知

每步开头先发一次阶段通知，再做该步的操作；同一个标签反复发就是更新同一条通知，不会刷屏。

```
cmd notification post -t "Hermes 手机任务" hermes-phone-task "阶段：核对会话标题"
```

- 标题固定为 `Hermes 手机任务`，标签固定为 `hermes-phone-task`。
- 正文只写阶段，不写消息内容、不写对方名字。通知栏在锁屏也可能可见，阶段文字越通用越好，例如：`阶段：打开微信` / `阶段：核对会话标题` / `阶段：输入消息` / `阶段：发送` / `阶段：恢复输入法`。
- 正常结束最后发 `阶段：已完成`；中途失败或停下最后发 `阶段：任务中断`，不要让通知栏一直停在旧的“进行中”阶段。
- 已知限制（Android 16 实测）：系统命令只有发、没有删，这条通知要用户自己在通知栏划掉；不要为了“删通知”去试没有验证过的系统调用。

## 为什么不上流体云药丸

实测结论：

- shell 通知只在通知栏，不上药丸。
- Termux 常驻通知实测也没上药丸。
- 药丸（流体云 / 实时提醒）要走 Android 16 实时更新：常驻、带进度或简短关键文字的实时更新通知，由一个真正的应用发出。shell 命令和 Termux 通知工具都发不出这种通知。

所以本项目现阶段不做药丸，只做通知栏阶段提示。如果以后要做药丸，需要另外做一个能发实时更新通知的手机应用，再由 Hermes 发广播触发它，不在本项目的范围里。

## Termux 通知和这个办法的关系

- Termux 通知能发常驻通知，也能用命令删掉，比 shell 命令的生命周期干净。
- 但 phone_exec 走 adb shell，跑不了 termux-* 命令（实测权限拒绝），Termux 通知只能在 Termux 会话里跑。
- 所以 Termux 通知在本项目里只能当通知栏的另一种实现，不能当药丸的捷径，也不能直接塞进 phone_exec 的步骤里。
