# 安全边界

先把这几条定下来，再动手。违反任何一条，就停下。

## 绝不做

- 不输密码、PIN、验证码、二次验证 code。出现这类输入框，停下，把手机交回用户。
- 不做支付、购买、转账、订阅。下单、付款前必须停下，先报价格、等用户明确说买。
- 不删消息、删文件、改系统设置（临时切输入法除外，且事后必须恢复并核对）。
- 不点任何“同意隐私协议”“同意并使用”“授权”弹窗。出现这类弹窗，返回上一步，不要替用户同意。
- 不给真人发敏感内容、不把读屏看到的其他会话、其他人的消息内容外传。汇报只写目标会话、目标消息、时间、核对结果。

## 审批

- 交互会话里，`phone_exec` 每次调用都要用户批一次，不要绕过。
- 不要开分类器自动运行（`classifier_auto_run`）：它是启发式判断，可以被绕过，脚本仍可能跑到本机。
- 单次运行（`hermes -z`）会按设计自动跳过审批，只用在你自己明确说的测试里，并在汇报里写明。
- 不要把 `phone_exec` 挂到任何公开机器人、群聊、消息平台上：能被陌生人调到的 phone_exec，就是别人在动你的手机。
- Telemetry 默认关着就关着，不要开。

## 每次任务的核对点

1. 标题：进会话先核对顶部标题逐字等于目标名，不对就退出，不输入、不发送。
2. 输入框：发送前核对输入框内容逐字等于目标消息，不对就停下，不猜、不凑。
3. 只发一次：成功后不要再发第二条，不要“补发一条确认一下”。
4. 收尾：新气泡、输入框已空、输入法已恢复，三点都核对了再汇报。
5. 超时/中断后：先查输入框和输入法，再决定补发还是重跑，不要盲目重输。
   运行环境本身被重启杀掉、汇报丢了，也不等于没做：先只读核对标题、气泡数、
   输入框、输入法，再决定，见 `docs/reliability.md` 第 3 节。

## 仓库里不能出现的东西

- 密钥、私钥、密码、Token、验证码、配对码
- 真实服务器 IP、真实手机号、真实账号、真实聊天内容、真实截图
- 你的 Hermes 配置、API key、支付资料

检查方法：提交前在仓库里搜一遍 IP、手机号、账号、密钥文件名，确认只剩占位符。模板脚本里故意只写 `YOUR_…`，不要填真实值。
