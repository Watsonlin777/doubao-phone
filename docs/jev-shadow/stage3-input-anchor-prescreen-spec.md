# Stage 3：输入框/锚点预筛影子定义（只记录、不改行为、不替代确定性核对）

## 位置与红线

- 本阶段是方案中风险顺序的第 3 项。前两项已落地影子记录：
  等待/稳定（v1.3.13，run 20261027-1644 与 20261027-1705 各积累 W1/W2）、
  标题预筛（v1.3.14，run 20261027-1705 积累 T1/T2，title_match 均为 true）。
- 红线不变：输入框空、输入读回、底部窗口锚点三项确定性核对永远是最终门。
  Jev 预筛只能做一件事：在确定性核对之前，预判“当前屏上的输入框/锚点状态是否值得按老规则再读一次”，
  或在核对未通过时，判断“是否值得重读一次再判”。
  Jev 说通过，仍须走确定性核对；Jev 说不通过或低置信度，一律按“重读 / 停下”处理，
  绝不据此直接输入、直接发送、清空输入框、跳过核对。
- 本阶段只定义问题、阈值与影子格式，并给生产 skill 加影子记录。任务内禁止调用 Jev，Jev 判断一律任务结束后离线做。

## 决策点

- I1：进入目标会话后，输入框空核对时（切输入法之前）。
- P2：点发送前，二次核对时（标题 + 输入框 + 底部窗口锚点同一屏核对时，只记输入框与锚点两项，标题仍按 T2 记，不重复）。
- 其他步骤不记录。发送后的底部窗口核对仍按老规则做，不另起预筛记录。

## 固定 Jev 问题（离线复现时用，任务内不问）

三个问题，英文原文固定不变，均为 `noul`，按决策点分开用，绝不混用：

I1 输入框空问题（只用于 I1）：

`"Is the message input box currently empty, with no draft text and no leftover characters?"`

P2 输入读回问题（只用于 P2，2026-10-27 修正）：

`"Does the message input box content exactly match the expected message, character for character, with no extra or missing characters?"`

锚点问题（只用于 P2）：

`"Is the bottom message window anchor visible on this screen, so a before-send baseline can be recorded?"`

修正说明：2026-10-27 真实 Jev 对照中，P2 曾误用了 I1 的空问题（P2 输入本应非空，Jev 给 0.44 实际正确），
该条判断已作废、不计入统计；修正后 P2 输入问题一律用上面这条读回相等问题，阈值仍为 0.90。

- 离线时给 Jev 的只含状态摘要，不含消息原文、标题原文、联系人姓名。
  影子文件本身只记布尔值，见下。

## 初始阈值

- 输入框：`noul >= 0.90` 才记为影子判断 empty/match，低于阈值、Jev 不可用或数据缺失均记为 unknown。
  输入框与发送直接相关，阈值与标题预筛同为 0.90。
- 锚点：`noul >= 0.85` 才记为影子判断 visible，低于阈值均记为 unknown。
  锚点误判不会直接导致误发，只会影响发送前后核对的基线可信度，故阈值略低于输入框，但仍高于等待/稳定的 0.80。
- 阈值不是上线标准：上线讨论须另看样本数、安全误放行样本是否为零、以及与老逻辑的一致率。

## 影子 JSONL 格式

文件：任务工作目录下 `jev-input-anchor-shadow-<run-id>.jsonl`，与等待/稳定、标题文件分开。
每行字段：

- `run_id`：本趟运行标识
- `decision_point`：I1 或 P2
- `input_empty`：I1 时老逻辑输入框空核对结果，true/false；P2 时不适用，记 null
- `input_match`：P2 时老逻辑输入读回与预期逐字相等结果，true/false；I1 时不适用，记 null
- `anchor_visible`：P2 时老逻辑底部窗口锚点可见结果，true/false；I1 时不适用，记 null
- `readback_ok`：该次读屏是否成功，true/false
- `step_seconds`：该核对步骤耗时（秒）
- 离线复现时追加：`jev_noul_input`、`jev_noul_anchor`、`jev_judgement`、`jev_latency_ms`、`jev_provider`（typesafe）、`agree`

只记布尔值与耗时，不记消息原文、标题原文、联系人姓名、聊天内容。

## 影子记录规则（给 skill 的附录，生产行为不动）

- 仅在 I1、P2 确定性核对完成后记一行，记录失败忽略并继续，绝不因记录失败而停下、中断、清空或重发。
- 禁止在任务内调用 Jev、调用任何决策接口、等待 Jev 返回后再继续。
- 禁止因快照记录而跳过输入框空核对、跳过输入读回、跳过底部窗口锚点、跳过二次核对。
- 禁止把快照写进生产任务状态文件，生产状态行与看门狗统计一律不动。
- 禁止把手机任务数据发给免费 Jev 通道；离线 Jev 一律走已验证的 TypeSafe 通道。

## 上线标准（本阶段不进入上线讨论）

- 样本数足够、且安全误放行样本为零、且效率收益有实测支撑时，才单独讨论是否把输入框/锚点预筛用作“是否重读”的辅助决策。
- 即使上线，Jev 预筛也只能决定“重读一次还是按老逻辑停下”，不能决定“输入、发送、清空”。
- 任何一趟出现误判导致误发、多发、清空或跳过核对，即停掉该类判断并恢复。
