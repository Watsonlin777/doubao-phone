# Stage 2：标题预筛影子定义（只记录、不改行为、不替代精确核对）

## 位置与红线

- 本阶段是方案中风险顺序的第 2 项（第 1 项等待/稳定已在 v1.3.13 落地影子记录，并于 run 20261027-1644 首次积累 W1/W2 各 1 行）。
- 红线不变：标题精确核对永远是确定性最终门。Jev 给的是概率，不是逐字相等。
  Jev 标题预筛只能做一件事：在精确核对之前，预判“当前屏上的标题是否值得按精确规则再读一次”，
  或在精确核对未通过时，判断“是否值得重读一次再判”。
  Jev 说通过，仍须走精确逐字核对；Jev 说不通过或低置信度，一律按“重读 / 停下”处理，绝不据此直接发送、绝不跳过精确核对。
- 本阶段只定义问题、阈值与影子格式，并给生产 skill 加影子记录。任务内禁止调用 Jev，Jev 判断一律任务结束后离线做。

## 决策点

- T1：进入目标会话后，第一次标题核对时。
- T2：点发送前，第二次标题核对时。
- 其他步骤不记录。标题被横幅遮挡（W3）时，仍按 W3 的等待/稳定快照记，不另起 T 记录，避免同一屏重复记两条。

## 固定 Jev 问题（离线复现时用，任务内不问）

英文原文，固定不变：

`"Does the screen title exactly match the expected recipient name, character for character, with no extra or missing characters?"`

- 问题类型：`noul`。
- 输入给 Jev 的不是标题原文全文：离线时只给“屏上读到的标题是否与预期逐字相等”这一判断的摘要，
  即老逻辑的精确核对结果（match true/false）与读屏是否成功，不把联系人姓名原文写进 Jev 请求以外的影子文件。
  影子文件本身只记布尔值，见下。

## 初始阈值

- `noul >= 0.90` 才记为影子判断 match，低于阈值、Jev 不可用或数据缺失均记为 unknown。
- 阈值高于等待/稳定的 0.80，因为标题是发送安全的最终门，误放行的代价远高于多等一次。
- 阈值不是上线标准：上线讨论须另看样本数、安全误放行样本是否为零、以及与老逻辑的一致率。

## 影子 JSONL 格式

文件：任务工作目录下 `jev-title-shadow-<run-id>.jsonl`，与等待/稳定文件分开，避免字段混用。
每行字段：

- `run_id`：本趟运行标识
- `decision_point`：T1 或 T2
- `title_match`：老逻辑精确核对结果，true/false（只记布尔值，不记标题原文、不记联系人姓名）
- `readback_ok`：该次标题读屏是否成功，true/false
- `step_seconds`：该标题核对步骤耗时（秒）
- 离线复现时追加：`jev_noul`、`jev_judgement`（match/unknown）、`jev_latency_ms`、`jev_provider`（typesafe）、`agree`（Jev 判断与老逻辑是否一致）

## 影子记录规则（给 skill 的附录，生产行为不动）

- 仅在 T1、T2 精确核对完成后记一行，记录失败忽略并继续，绝不因记录失败而停下、中断或重发。
- 禁止在任务内调用 Jev、调用任何决策接口、等待 Jev 返回后再继续。
- 禁止把快照写进生产任务状态文件，生产状态行与看门狗统计一律不动。
- 禁止把手机任务数据发给免费 Jev 通道；离线 Jev 一律走已验证的 TypeSafe 通道。
- 标题原文、聊天内容、联系人姓名一律不进影子文件。

## 上线标准（本阶段不进入上线讨论）

- 样本数足够、且安全误放行样本为零、且效率收益有实测支撑时，才单独讨论是否把标题预筛用作“是否重读”的辅助决策。
- 即使上线，Jev 预筛也只能决定“重读一次还是按老逻辑停下”，不能决定“发送”。
- 任何一趟出现误判导致误发、多发或跳过精确核对，即停掉该类判断并恢复。
