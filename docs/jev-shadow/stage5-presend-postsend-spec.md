# Stage 5：发前门与发后核对影子定义（只记录、不改行为、不替代用户确认与确定性核对）

## 位置与红线

- 本阶段是方案中风险顺序的第 5 项，也是最后一项。前四项已落地影子记录：
  等待/稳定（v1.3.13）、标题预筛（v1.3.14）、输入框/锚点预筛（v1.3.15）、下一步动作（v1.3.16）。
- 红线不变，且本阶段最严：
  1. 发送永远只发一次，且必须同时有收件人、完整内容、用户当次明确确认，缺一即停；
     Jev 发前门只能是附加记录，不能替代用户确认，不能替代标题、输入框、底部窗口三项确定性核对。
  2. 发后核对永远按底部窗口“恰好加一”判定；Jev 发后判断不能把“未知”说成“已发出”，也不能把“已发出”说成“未发出”而诱发重发。
  3. 中断后一律 fail-closed：有 send_after 且底部窗口通过才按已发出处理，否则按未知，绝不重发。
- 本阶段只定义问题、阈值与影子格式，并给生产 skill 加影子记录。任务内禁止调用 Jev，Jev 判断一律任务结束后离线做。

## 决策点

- G1：点发送前，发前门核对完成时（标题、输入框、底部窗口锚点、用户确认四项确定性条件全部核对完之后，点发送之前）。
- G2：点发送后，收尾核对完成时（verify_after 之后，恢复之前）。
- 其他步骤不记录。发前门与发后核对各记一行，共用一个影子文件，decision_point 区分。

## 固定 Jev 问题（离线复现时用，任务内不问）

两个问题，英文原文固定不变，均为 `noul`：

发前门问题：

`"Is every pre-send gate condition met, with the recipient, content, and user confirmation all present and all deterministic checks passed?"`

发后核对问题：

`"Did the bottom message window increase by exactly one sent bubble after the send action?"`

- 离线时给 Jev 的只含状态摘要（各确定性核对是否通过、send_after 是否存在、底部窗口计数变化是否为 1），
  不含消息原文、标题原文、联系人姓名。
- 影子文件本身只记布尔值，见下。

## 初始阈值

- 发前门：`noul >= 0.95` 才记为影子判断 gate_pass，低于阈值、Jev 不可用或数据缺失均记为 unknown。
  发前门离发送最近，阈值定为全方案最高 0.95。
- 发后核对：`noul >= 0.90` 才记为影子判断 plus_one，低于阈值均记为 unknown。
- 阈值不是上线标准：上线讨论须另看样本数、安全误放行样本是否为零、以及与老逻辑的一致率。
  发前门与发后核对即使将来讨论上线，也只能用作“是否重读/是否停下”的辅助，不能用作“是否发送”的决定。

## 影子 JSONL 格式

文件：任务工作目录下 `jev-presend-postsend-shadow-<run-id>.jsonl`。
每行字段：

- `run_id`：本趟运行标识
- `decision_point`：G1 或 G2
- `gate_pass`：G1 时四项确定性条件是否全部通过，true/false；G2 时不适用，记 null
- `send_after_present`：G2 时 send_after 是否存在，true/false；G1 时不适用，记 null
- `plus_one`：G2 时底部窗口是否恰好加一，true/false；G1 时不适用，记 null
- `readback_ok`：该次核对读屏是否成功，true/false
- `step_seconds`：该核对步骤耗时（秒）
- 离线复现时追加：`jev_noul`、`jev_judgement`、`jev_latency_ms`、`jev_provider`（typesafe）、`agree`

只记布尔值与耗时，不记消息原文、标题原文、联系人姓名、聊天内容。

## 影子记录规则（给 skill 的附录，生产行为不动）

- 仅在 G1、G2 确定性核对完成后记一行，记录失败忽略并继续，绝不因记录失败而停下、中断或重发。
  注意：G2 记录失败不改变“已发出/未知”的判定，判定仍以状态行与底部窗口为准。
- 禁止在任务内调用 Jev、调用任何决策接口、等待 Jev 返回后再继续。
- 禁止因快照记录而跳过用户确认、跳过标题、输入框、底部窗口核对、跳过二次核对、跳过恢复。
- 禁止把快照写进生产任务状态文件，生产状态行与看门狗统计一律不动。
- 禁止把手机任务数据发给免费 Jev 通道；离线 Jev 一律走已验证的 TypeSafe 通道。

## 上线标准（本阶段不进入上线讨论）

- 样本数足够、且安全误放行样本为零、且效率收益有实测支撑时，才单独讨论发前门/发后核对是否可用作辅助。
- 即使讨论上线，发前门也只能是附加门，不能替代用户当次确认；发后核对也只能是辅助复核，不能改变 fail-closed 判定。
- 任何一趟出现误判导致误发、多发、跳过确认或跳过核对，即停掉该类判断并恢复。
- 本阶段完成后，五类影子记录全部就绪；下一步是等用户单独授权的手机任务积累全套样本，而不是自动进入上线。
