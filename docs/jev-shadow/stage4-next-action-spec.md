# Stage 4：下一步动作影子定义（只记录、不改行为、不替代老逻辑规划）

## 位置与红线

- 本阶段是方案中风险顺序的第 4 项。前三项已落地影子记录：
  等待/稳定（v1.3.13）、标题预筛（v1.3.14）、输入框/锚点预筛（v1.3.15）。
- 红线不变：下一步动作永远由老逻辑的步骤顺序与确定性核对决定。
  Jev 只能在事后对照“老逻辑选的下一步是否与 Jev 的选择一致”，不能在任务内改变步骤顺序、
  不能跳过核对、不能提前发送、不能把“重读”改成“发送”。
- 本阶段只定义问题、阈值与影子格式，并给生产 skill 加影子记录。任务内禁止调用 Jev，Jev 判断一律任务结束后离线做。

## 决策点

只记两个关键转折点，不记每一步，避免快照泛滥：

- N1：标题核对通过后，下一步是“继续输入”还是“停下”。
- N2：输入读回通过后，下一步是“继续二次核对/发送流程”还是“停下”。
- 其他步骤转折不记录。停下、重读、回退等老逻辑动作本身仍按 skill 走，快照只记录老逻辑当时选的动作标签。

## 固定 Jev 问题（离线复现时用，任务内不问）

英文原文，固定不变，类型为 `choice`，选项固定为三项：

`"What is the safest next action: proceed, re-read, or stop?"`

- 选项：`proceed` / `re-read` / `stop`，不增加第四项，不把“发送”单独列为选项，
  因为发送只是“继续二次核对/发送流程”里被多重门控住的一步，绝不是 Jev 可以直接选的动作。
- 离线时给 Jev 的只含状态摘要（当前阶段、核对是否通过、读屏是否成功），不含消息原文、标题原文、联系人姓名。

## 初始阈值

- 选择置信度 `>= 0.85` 才记为影子判断，否则记为 unknown。
- 低于阈值、Jev 不可用或数据缺失均记为 unknown，unknown 永远不等于“继续”，只等于“按老逻辑走”。
- 阈值不是上线标准：上线讨论须另看样本数、安全误放行样本是否为零、以及与老逻辑的一致率。

## 影子 JSONL 格式

文件：任务工作目录下 `jev-next-action-shadow-<run-id>.jsonl`。
每行字段：

- `run_id`：本趟运行标识
- `decision_point`：N1 或 N2
- `next_action`：老逻辑当时选的动作标签，`proceed` / `re-read` / `stop`（只记标签，不记动作细节）
- `check_passed`：该转折点前的确定性核对是否通过，true/false
- `readback_ok`：该次读屏是否成功，true/false
- `step_seconds`：该步骤耗时（秒）
- 离线复现时追加：`jev_choice`、`jev_confidence`、`jev_latency_ms`、`jev_provider`（typesafe）、`agree`

只记标签与布尔值，不记消息原文、标题原文、联系人姓名、聊天内容。

## 影子记录规则（给 skill 的附录，生产行为不动）

- 仅在 N1、N2 老逻辑动作选定后记一行，记录失败忽略并继续，绝不因记录失败而停下、中断或重发。
- 禁止在任务内调用 Jev、调用任何决策接口、等待 Jev 返回后再继续。
- 禁止因快照记录而改变步骤顺序、跳过核对、提前发送。
- 禁止把快照写进生产任务状态文件，生产状态行与看门狗统计一律不动。
- 禁止把手机任务数据发给免费 Jev 通道；离线 Jev 一律走已验证的 TypeSafe 通道。

## 上线标准（本阶段不进入上线讨论）

- 样本数足够、且安全误放行样本为零、且效率收益有实测支撑时，才单独讨论是否把下一步动作选择用作“是否重读”的辅助决策。
- 即使上线，Jev 选择也只能在 proceed / re-read / stop 三项内起辅助作用，不能直接选“发送”。
- 任何一趟出现误判导致误发、多发、跳过核对，即停掉该类判断并恢复。
